# Instructions - Étape 8 : Distributions (cadeaux via Google Sheet) & Historique

## Objectif
Permettre à l'utilisateur de "vérifier les distributions" : l'app lit un CSV public (Google Sheet), repère les lignes destinées à son UUID, applique les récompenses une seule fois, et affiche le résultat.

## Fichiers
- `js/business/GiftManager.js`, `js/UI/views/GiftsView.js`, `css/views/gifts.css`
- Mise à jour de `settings/config.json`, `SettingsView.js`, `index.html` (section Cadeaux), `i18n/*.json`

## Format du Google Sheet
Ligne 1 = en-tête. Colonnes : `uuid`, `type` (`booster` | `card`), `key`, `quantity`. La colonne `key` identifie ce qui est offert, pour les deux types :
- `booster` : `key` = identifiant de l'extension (ex. `set1`), `quantity` = nombre de boosters bonus **de cette extension**.
- `card` : `key` = clé unique de la carte (`id_style`, ex. `042_fullart`), `quantity` = nombre d'exemplaires.
- `key` vide ou inconnue (set ou carte introuvable dans les JSON) : ligne ignorée avec avertissement, mais marquée traitée pour ne pas être retentée.
- **Règle de gestion du sheet : append-only.** Ne jamais trier, insérer ou supprimer de lignes, sinon les numéros de ligne changent.

## Spécifications

1. **`settings/config.json`** : `giftSheet: { id: "1AodjgWkMej5Hrt1jcs_DH-dCo87A-3vR7NyiINkKUSA", gid: "0" }`. Le fetch construit l'URL CSV à partir de l'id (essayer `https://docs.google.com/spreadsheets/d/<id>/gviz/tq?tqx=out:csv&gid=<gid>`, puis `.../export?format=csv&gid=<gid>` en repli). Le sheet doit être partagé "toute personne disposant du lien". **À tester** : le comportement CORS depuis le navigateur.

2. **`GiftManager.js`** — `async checkGifts()` :
   1. Récupère le CSV. Réseau/CORS en échec → erreur claire, **`lastCheckedLine` inchangé**.
   2. Parse le CSV (guillemets, virgules et fins de ligne gérés). Le numéro de ligne = index dans le fichier, en-tête = ligne 1.
   3. Lit `giftSync.lastCheckedLine` et l'UUID du compte (comparaison insensible à la casse et aux espaces).
   4. Pour chaque ligne `n > lastCheckedLine` dont l'uuid correspond : valide `type` et `quantity` (entier > 0), applique la récompense (`addBonusBoosters(key, quantity)` ou `addCardToCollection(carte de key, quantity)`) et écrit `gifts_received[n] = { line: n, uuid, type, key, quantity, receivedAt }`.
   5. Dans **une seule transaction** : toutes les récompenses + les enregistrements + `giftSync = { lastCheckedLine: <dernière ligne lue>, lastCheckAt }`.
   6. Anti-doublon : `gifts_received` est indexé par n° de ligne, et une ligne déjà présente est ignorée même si `lastCheckedLine` a été altéré (ex. import d'une vieille sauvegarde).
   7. Retourne `{ received: [...], scannedFrom, scannedTo }`.

3. **Interface**
   - Paramètres → bouton **"Vérifier les distributions"** (état chargement, désactivé pendant la vérification).
   - Résultat dans un modal : liste "Vous avez reçu : 2 boosters, carte X ×1…" ou "Aucun cadeau pour le moment". Toast d'erreur si le réseau échoue.
   - Lien **"Historique des cadeaux"** → vue `GiftsView` : liste triée du plus récent au plus ancien (n° de ligne, date, type, `key` résolue en nom de set ou de carte, quantité, aperçu de la carte). Message si vide. Affichage aussi de la date de dernière vérification.
   - Le header (compteur de boosters) se met à jour via `QUOTA_UPDATED`.

4. **Limites à documenter** (commentaire en tête de `GiftManager.js`) : l'UUID étant dans un sheet public, toute personne connaissant le lien voit les UUID et cadeaux de tous ; le contrôle "une seule fois" est purement local (côté client, contournable). Acceptable pour un jeu sans enjeu ; à ne pas utiliser pour des récompenses de valeur.
