# Instructions - Étape 7 : Codes de Distribution (Redeem) & Finitions Mobile

## Fichiers
- `settings/redeem.json`, `css/views/redeem.css`
- `js/business/RedeemManager.js`, `js/UI/views/RedeemView.js`, `js/UI/components/Toast.js`

## Spécifications

1. **`settings/redeem.json`**
```json
[
  { "code": "LAUNCH2026", "type": "booster_grant", "reward": { "amount": 2 }, "expiration": "2026-12-31" },
  { "code": "MYTHICGIFT", "type": "card_grant", "reward": { "cardId": "042", "style": "fullart", "set": "set1" } }
]
```

2. **`RedeemManager.js`**
   - Code insensible à la casse ; refuse un code inconnu, expiré (jour UTC fiable de `DateSyncManager`, pas `Date.now()`) ou déjà présent dans `redeemed_codes`.
   - `booster_grant` → `DateSyncManager.addBonusBoosters(amount)` (**solde bonus, non écrasé par le reset de minuit**).
   - `card_grant` → `BoosterManager.addCardToCollection(card, 1)`.
   - Enregistrement du code dans `redeemed_codes` et application de la récompense dans la même transaction.

3. **`RedeemView.js`** : champ de saisie, toasts succès/erreur (traduits via `I18n.t`), affichage de la récompense obtenue.

4. **Finitions mobile (à appliquer globalement, dans `base.css`)**
   - `touch-action: manipulation` sur les boutons, `overscroll-behavior: none`.
   - Vérifier : pas de scroll horizontal, zones ≥ 44px, animations limitées à `transform`/`opacity`, `will-change` ciblé, `prefers-reduced-motion` respecté, lisibilité des 3 thèmes.

Génère le code complet et l'intégration finale.
